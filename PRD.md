# PART A — BRAND IDENTITY

## 1. Brand Overview

**Brand Name:** ORÉVA

**Descriptor:** Jewellery House

**Tagline:** Elegance, Made Eternal.

**Positioning:** Contemporary Accessible Luxury Jewellery.

ORÉVA is a contemporary jewellery brand built around elegance, individuality and timeless design. It presents curated jewellery through sophisticated visual storytelling and premium customer experiences.

# PART C — FUNCTIONAL REQUIREMENTS

## 1. Product Catalogue

Products should be organised into manageable categories.

Product information:

- Product name.
- Slug.
- SKU.
- Description.
- Price.
- Original price (optional).
- Multiple images.
- Category.
- Collection.
- Gender.
- Variants (optional).
- Availability.
- Featured status.
- New arrival status.
- Bestseller status.
- Publication status.

## 2. Product Discovery

Customers should be able to:

- Browse all products.
- Browse by category.
- Browse by collection.
- Browse men's and women's products.
- Search products.
- Filter by price and category.
- View individual product details.
- Explore related products.

## 3. Product Details

Individual product pages should include:

- Product image gallery.
- Product name.
- Product code.
- Price.
- Description.
- Product specifications.
- Available variants.
- Related products.
- WhatsApp enquiry CTA.

## 4. WhatsApp Enquiries

WhatsApp is the primary conversion mechanism.

Each product should have an enquiry action.

Generate a prefilled WhatsApp message containing:

- Brand name.
- Product name.
- Product SKU.
- Product URL.
- Customer enquiry prompt.

The destination WhatsApp number must be configurable through admin settings.

Record enquiry clicks in MongoDB for basic analytics.

Customers should not need to create an account.

## 5. Search

Provide lightweight product search.

Search should match:

- Product names.
- Product codes.
- Categories.
- Collection names.

## 6. Wishlist

Wishlist functionality is optional for the initial release.

If implemented, visitors should be able to save products for later using local persistence or account-based persistence.

## 7. Newsletter

Allow visitors to subscribe to brand updates.

Store subscriptions securely and provide appropriate consent and unsubscribe handling.

## 8. Contact

Provide:

- WhatsApp contact.
- Contact form.
- Business email.
- Social media links.

# PART F — TECHNICAL ARCHITECTURE

## 1. Technology Stack

**Frontend**

- Next.js App Router.
- React.
- TypeScript.
- Tailwind CSS.
- shadcn/ui.

**Backend**

- Next.js Server Actions.
- Route Handlers where appropriate.
- MongoDB native driver.
- Zod validation.

**Authentication**

- Better Auth or an appropriately secured admin authentication solution.

**Media**

- Cloudinary or another managed image-storage provider.

**Animations**

- Motion or GSAP
- ScrollTrigger.

**Deployment**

- Vercel.
- MongoDB Atlas.

## 2. Architecture Principles

- Server Components by default.
- Client Components only where interactivity is required.
- Reusable and modular components.
- Centralised database access.
- Server-side input validation.
- Protected admin routes and mutations.
- SEO-friendly product and category pages.
- Cache-aware catalogue queries.
- Appropriate cache revalidation after admin content updates.

## 3. Image Management

- Use managed image storage.
- Never store raw image files directly in MongoDB.
- Optimise image dimensions and formats.
- Generate responsive image variants where appropriate.
- Use lazy loading below the fold.
- Maintain consistent image aspect ratios.

## 4. Caching

The public catalogue should use appropriate Next.js caching and revalidation.

When an administrator publishes or updates a product, the relevant public pages should update without requiring a new deployment.

# PART G — DESIGN SYSTEM & USER EXPERIENCE

## 1. Design Principles

1. Luxury through simplicity.
2. Photography takes priority over decoration.
3. Generous whitespace.
4. Clear visual hierarchy.
5. Consistent burgundy and champagne palette.
6. Elegant serif typography.
7. Minimal but meaningful animations.
8. Consistent product image presentation.

## 2. Animation Direction

Use GSAP for:

- Hero text entrance.
- Image reveal animations.
- Scroll-triggered section entrances.
- Collection card hover effects.
- Editorial image transitions.
- Subtle navigation transitions.

Avoid:

- Excessive parallax.
- Unnecessary animated elements.
- Heavy scroll-jacking.
- Animations that delay content visibility.

Respect reduced-motion preferences.

## 3. Responsive Design

Support:

- Desktop.
- Laptop.
- Tablet.
- Mobile.

Mobile priorities:

- Touch-friendly navigation.
- Readable product information.
- Smooth horizontal carousels.
- Proper image cropping.
- Prominent WhatsApp enquiry buttons.
- Optimised performance.

Mobile should have an intentionally designed layout rather than simply shrinking the desktop version.

# PART I — SECURITY REQUIREMENTS

- Secure admin authentication.
- Role-based access where necessary.
- Server-side authorisation on every protected mutation.
- Validate inputs using Zod.
- Validate uploaded image types and sizes.
- Prevent unauthorised product modifications.
